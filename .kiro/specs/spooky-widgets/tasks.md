# Implementation Plan: spooky-widgets

## Overview

Build the spooky widgets in the order the user fixed, one task at a time, each ending in a checked state. First `SeededRandom` moves to `lib/src/common/` as a pure move, with its own full `coffin_core` test run (exactly 985 passing tests) and the pubspec baseline recorded. Then the pure math (`PingPong`, `GhostBob`, `FlickerSchedule`, `FogParticle`, `FogDisc`, `FogField`) with web-safe generators and glados property tests, then Checkpoint A with a Chrome run that also settles open decision N4. Then the widgets (`SpookyTokens`, `MotionLoop`, `GhostPainter`, `GhostLoader`, `TombstoneBorder`, `TombstoneCard`, `FlickerText`, `FogBackground`) with widget tests and the VM-only source scan, then Checkpoint B. Then `CryptGallery`, the Barrel exports with their test, and the Hauntagotchi `/gallery` route. The last task is the final checkpoint: format, analyze, all tests, Chrome run, two web builds, the pubspec and lockfile hash comparison, a scope check, a secrets grep and a plain "not verified" statement.

All code is Dart in Flutter, following `design.md`. Paths are relative to the repo root `/Users/ranmanlabs/Documents/Kiroween/coffin`. Tests use `flutter_test` and `glados`. Every task is required. Nothing is optional.
