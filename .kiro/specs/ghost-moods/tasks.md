# Implementation Plan: ghost-moods

## Overview

Build ghost moods in the order fixed by Requirement 23.7, one task at a time, each ending in a checked state. First the baseline is recorded. Then `GhostMood` and the pure mood math (`MoodTraits`, `MoodPose`, `MoodBlend`, `MoodBob`, `MoodReaction`) with web-safe generators, unit tests and the eleven glados property tests, then Checkpoint A with a Chrome run of the pure tests. Then the painter and the loader (`MotionLoop` hook, `GhostPainter` mood and pose, `GhostLoader` mood path, transitions, reactions, the no-ticker rule for a settled `dead` ghost) with widget tests, then Checkpoint B. Then the Crypt gallery mood section, then Checkpoint C. Then the Hauntagotchi work (`moodFor`, controller events, `GhostPanel`, `HomeScreen` wiring and the 24 px top padding), then Checkpoint D. Then the README section. The last task is the final checkpoint: format, analyze, all four test suites, the Chrome run, two web builds, `git diff --stat` checks that `pubspec.yaml`, `pubspec.lock`, `DIARY.md`, `apps/graveyard` and `tool` are unchanged, a scope check, a secrets grep and a plain "not verified" statement.

All code is Dart in Flutter, following `design.md`. Paths are relative to the repo root `/Users/ranmanlabs/Documents/Kiroween/coffin`. Tests use `flutter_test` and `glados`. Every task is required. No test task is optional.
